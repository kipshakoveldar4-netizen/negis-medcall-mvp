## Missing Evidence That Can Invalidate Release

1. **Explicit-ID capacity parity is unresolved.** UI excludes a different non-null doctor ID even with the same name ([caller](../../artifacts/negis/src/pages/AppointmentsPage.tsx#L2273)); API preflight selects by `doctor_name` ([server](../../lib/crm/server.ts#L2833)); 073 counts `doctor_id = any(doctor_ids) OR matching name`, without limiting the name branch to unlinked rows ([SQL](../../migrations/073_peak_appointment_capacity.sql#L115)). Thus a full namesake's group can falsely refuse a free explicit-ID group. This is source-demonstrated disagreement, not a native/live reproduction; no later migration replaces this guard.
2. **The decisive proofs use different schema subsets.** Route/PGlite setup loads 063/064 plus 076 but NOT 072/073 ([setup](../../scripts/src/medina-arrival-payment.test.ts#L32)); native capacity setup adds 072/073 but NOT 076 ([setup](../../scripts/fixtures/appointment-capacity-postgres.test.mjs#L103)). Its cases do not cover two explicit same-name doctor IDs. Neither suite establishes caller -> current API -> combined schema capacity/recovery parity; historical aggregate chain totals are not that acceptance.
3. **Committed replay/unmount remains split.** The real React/HTTP committed suite has no explicit committed unmount/remount case. Extracted-hook `actual layout cleanup invalidates captured actions and unsubscribes the raw SDK observer` exists separately ([test](../../scripts/src/medina-appointment-access-denial.test.ts#L781)); it cannot stand in for committed SQL-backed replay across remount. Main's repaired hidden-form cases above do not close this separate composed SQL-backed lane.
4. **Task lifetime is not generic task exactly-once.** TaskPanel POST has no durable request key and keeps its draft after unknown failure ([caller](../../artifacts/negis/src/components/crm/task-panel.tsx#L340)); the synchronous click mutex does not prove safe retry after commit/lost ACK. Existing `lost close response is not falsely reported as a cancelled change` ([test](../../scripts/src/medina-task-panel-lifetime.test.ts#L331)) is honest messaging, not durable creation recovery.
5. **Postponed target completeness is unproven here.** [080](../../migrations/080_postponed_lead_stage.sql#L31) replaces the seed function; it does not seed every existing workspace automatically. UI fallback/canonical labels cannot attest persisted active stages on a selected target. Preserve custom/unchanged stages and prove a selected current transition/reload/filter round trip; no mortgage/Baspana live checks were performed.
