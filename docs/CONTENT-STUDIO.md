# Контент-студия: что делает продукт и что остаётся делать руками

Экран `/content-studio`. Разделы сверху вниз: пакет контента, генерация
изображения и видео, фото-креатив из загруженной фотографии, идея ролика,
сценарий, два prompt-раздела, Telegram-handoff и схема «Как собирается ролик».

## Что действительно происходит

| Раздел | Что делает | Куда попадает результат |
|---|---|---|
| Пакет контента | `POST /api/content-studio/generate-package` — текстовая модель собирает сценарий, shot list, тексты объявления, photo/video prompt и WhatsApp-сообщение | состояние экрана + строка `content_videos` |
| **Генерация изображения** | `POST /api/content-studio/generate-photo` — модель изображений по описанию кадра | файл в bucket `ad-creatives`, строка в `ad_creative_assets`, ссылка на экране |
| **Генерация видео** | `POST /api/content-studio/generate-video` заводит задачу, `GET /api/content-studio/video-generation?handle=…` опрашивает её; готовый MP4 скачивается сервером | файл в bucket `ad-creatives`, строка в `ad_creative_assets` |
| Фото-креатив | макет собирается в браузере на canvas поверх загруженной фотографии — генерации здесь нет | подписанная загрузка в `ad-creatives` |
| Сценарий / Avatar / TapNow | текстовая модель, результат — текст для внешних инструментов | `content_videos` |
| Telegram | отправка собранного пакета текстом в чат платформы | — |

Сгенерированный файл сразу лежит в той же библиотеке креативов, из которой
берёт файлы «AI запуск рекламы»: кнопка «В AI запуск рекламы» переносит ссылку,
формат и тексты, ничего не перезагружая вручную.

## Что нужно настроить

Обе возможности работают на том же `OPENAI_API_KEY`, который уже тратится на
тексты. Отдельного вендора, отдельного счёта и отдельного секрета не появилось.

| Переменная | Обязательна | Что делает |
|---|---|---|
| `OPENAI_API_KEY` | да | без неё изображение и видео отвечают 503 «не подключено» |
| `CONTENT_STUDIO_IMAGE_MODEL` | нет | переопределяет модель изображений; по умолчанию `gpt-image-2` |
| `CONTENT_STUDIO_VIDEO_MODEL` | **да — для видео** | без неё кнопка видео отвечает 503 и ничего не тратит |
| `CONTENT_STUDIO_VIDEO_SECONDS` | нет | длительность ролика; пусто — умолчание провайдера |

**Почему у видеомодели нет значения по умолчанию.** Доступ к ней выдаётся
аккаунту отдельно, а один ролик стоит на порядок дороже картинки. Умолчание
означало бы, что кнопка появилась и списала деньги без решения владельца.
Пустая переменная — это не недоделка, это выключатель.

**Ключи в чат не передаются.** Значение переменной задаёт владелец в настройках
проекта Vercel своими руками. Ни один экран, лог, тест и отчёт значение не
печатает; наружу уходит только имя переменной.

## Чего в продукте нет

`ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `HEYGEN_API_KEY`, `TAPNOW_API_KEY`
лежат в `.env.example` и **не читаются кодом ни в одном месте**. Раздел
«Как собирается ролик» помечает озвучку, монтаж и публикацию как ручные шаги —
раньше он перечислял ElevenLabs, HeyGen и CapCut как часть цепочки продукта,
хотя ни одного вызова к ним не существует.

## Отказы: что увидит оператор

Никакой заглушки. Текст без ключа можно отдать заготовкой — она читается как
текст и приносит пользу; картинки-заготовки не существует, поэтому:

| Что случилось | Ответ | Что видно на экране |
|---|---|---|
| нет `OPENAI_API_KEY` | 503 | «Генерация изображений не подключена — не задана переменная OPENAI_API_KEY» |
| нет `CONTENT_STUDIO_VIDEO_MODEL` | 503 | то же с именем этой переменной |
| провайдер отклонил описание | 422 | текст отказа провайдера + совет переписать описание |
| исчерпан лимит или баланс | 429 | «сервис ограничил частоту запросов» |
| ключ платформы неверен | **502**, не 401 | 401 провайдера — это наш ключ, а не сессия оператора: выкидывать человека на экран входа из-за чужой проблемы нельзя |
| задача видео не удалась | 200 + `status: "failed"` | причина от провайдера, прогресс останавливается |

## Изоляция клиник

* Рабочее пространство берётся только из проверенного контекста. `workspaceId`
  из тела запроса не читается — это закреплено `test:api-surface-authorization`
  (S6) и `test:content-generation` (GEN19).
* Bucket и ключ объекта выводятся на сервере из проверенного `workspaceId` тем
  же билдером, что и ручная загрузка (Storage-1). Браузер их не выбирает.
* Идентификатор задачи видео уходит наружу подписанным HMAC по рабочему
  пространству. Без подписи сотрудник одной клиники, узнав чужой идентификатор,
  получил бы копию чужого ролика: провайдер про наши рабочие пространства ничего
  не знает. Проверяется GEN13–GEN15.
* Опрос состояния требует права `manage_ai_content`, а не права просмотра: он
  доводит готовый файл до библиотеки креативов, то есть пишет.

## Ограничения, о которых стоит знать заранее

* **Состояние задачи видео живёт до перезагрузки страницы.** Подписанный
  идентификатор хранится в состоянии React и намеренно не сохраняется: иначе
  повторный опрос уже готовой задачи скачал бы и записал тот же ролик второй раз.
* **Квадратного формата у видеомодели нет.** Feed 1:1 снимается вертикально
  9:16, и экран говорит об этом отдельной строкой, а не подменяет формат молча.
* **Время ответа.** Генерация изображения занимает десятки секунд, поэтому
  функции `api/content-studio/*` подняты до `maxDuration: 60` в `vercel.json`.
  Видео рендерится минутами — поэтому оно сделано задачей с опросом, а не одним
  долгим запросом.
* **Проверка формулировок не заменяет юриста.** `checkMetaCompliance` ищет
  известные запрещённые обороты в заголовке, тексте и подписи. Раньше на этом
  месте стояли пять зелёных галочек из постоянного массива — они появлялись
  всегда, независимо от текста. Теперь вердикт и цвет берутся из фактической
  проверки, а список правил подписан как перечень проверок, а не как результат.

## Что осталось незакрытым (знать заранее)

Найдено адверсарным ревью ветки; перечислено здесь, а не замолчано.

* **Ограничения частоты запросов нет.** Ни на этих маршрутах, ни в общем слое
  авторизации. Сотрудник с правом `manage_ai_content` — это владелец,
  администратор и маркетолог — может в цикле нажимать «Сгенерировать видео» и
  расходовать бюджет провайдера, пока тот не кончится. Единственный тормоз
  сегодня — `CONTENT_STUDIO_VIDEO_MODEL`: пока она пуста, видео не тратит
  ничего. Настоящий лимит требует счётчика, переживающего перезапуск функции,
  то есть таблицы; сделать его «в памяти» серверлесс-функции нельзя — это была
  бы имитация защиты, а не защита.
* **Ротация служебного ключа Supabase обрывает незавершённые задачи.** Подпись
  идентификатора выводится из него, поэтому после ротации уже оплаченные
  рендеры перестают опрашиваться и их файлы забрать нечем. Ключ подписи
  выводится отдельным HMAC с меткой назначения, так что сам служебный ключ из
  подписи не восстанавливается, но привязка к его сроку жизни остаётся.
* **Ролик читается в память целиком.** Предел 100 МБ отсекает файл до записи в
  хранилище, но не до чтения ответа. Потоковая передача из провайдера прямо в
  Supabase Storage потребовала бы другого клиента хранилища.
* **Повторяемость опроса держится на ключе объекта, а не на строке в базе.**
  Один и тот же `jobId` даёт один и тот же путь, объект перезаписывается, а
  строка ищется по этому пути перед вставкой. Если поиск не удастся (отказ
  базы), вставка всё же произойдёт: две строки видно и их можно удалить, а
  потерянный ролик — нельзя.

## Тесты

`pnpm run test:content-generation` — GEN1–GEN23: разбор ответов провайдера,
отказы без конфигурации, подпись идентификатора задачи, отсутствие ключа в
текстах ошибок, регистрация маршрутов и отсутствие придуманных данных на экране.
Сеть не трогается: `fetch` инжектируется.

Смежные наборы, которые тоже держат этот экран: `test:api-surface-authorization`
(S6, S7, S10, S19), `test:failure-honesty`, `test:tenant-isolation`.
