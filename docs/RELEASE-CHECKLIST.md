# Medina OS: контроль выпуска сайта и блога

Актуализировано 27 сентября 2026, цикл S3/S4. Это список условий выпуска,
**не разрешение на публикацию, изменение настроек или отправку тестовых заявок**.
Текущая очередь и выполненные проверки: [DELIVERY-CYCLES](DELIVERY-CYCLES.md).

Прежняя инструкция «запустить production и проверить всё» больше не действует.
Показатель readiness в Admin Center, особенно из localStorage, не подтверждает
готовность сайта. Проверки с записью данных выполняются только на изолированных
фикстурах либо в отдельно согласованной тестовой среде. Живые клиники не тестируем.
Новый облачный проект не создаём. Meta API не вызываем, ACTIVE не включаем.

## 2. Настройки текущего общего deployment

Это серверный `/ru/` в существующем catch-all, не отдельная статическая сборка.
Проверять выбранную среду в защищённой панели; значения не присылать в чат.

| Настройка | Условие для будущего включения |
|---|---|
| `MEDINA_PUBLIC_SITE_ENABLED` | `true` только после разрешения открыть сайт |
| `MEDINA_PUBLIC_SITE_WORKSPACE_ID` | Подтверждённое маркетинговое пространство |
| `MEDINA_SITE_ORIGIN` | Точный HTTPS origin, без пути и завершающего `/` |
| `MEDINA_SITE_INDEXABLE` | Отдельное разрешение на индексацию, до него не `true` |
| `MEDINA_SITE_FORM_ENABLED` | Явное разрешение показывать рабочую форму |
| `MEDINA_SITE_INTAKE_ENABLED` | Явное разрешение серверного приёма заявок |
| `MEDINA_SITE_INTAKE_KEY` | Ключ нужной серверной привязки, не параметр посетителя |
| `MEDINA_SITE_TURNSTILE_SITE_KEY` | Публичный ключ виджета нужного домена |
| `MEDINA_SITE_TURNSTILE_SECRET` | Соответствующий секрет только на сервере |
| Supabase server env | Только в защищённых настройках нужной среды |

В этом режиме `MEDINA_SITE_API_ORIGIN` и `MEDINA_SITE_CONSENT_VERSION`
не задают endpoint/версию формы: endpoint строится из `MEDINA_SITE_ORIGIN`,
версия читается из `crm_intake_sites`. Эти две переменные относятся к отдельной
локальной/статической сборке, не заменяют серверную привязку.

- [ ] Проверить настройки чтением панели нужной среды. Presence-флаги не
  доказывают правильность ключей, домена, прав или принадлежность пространства.
- [ ] Подтвердить наличие 058/059/060, не применять миграции повторно автоматически.
- [ ] В `crm_intake_sites` строка по `site_key` имеет тот же workspace, что сайт;
  `enabled` и версия согласия согласованы; `allowed_page_paths` включает `/ru/`.
  Сейчас форма на главной, остальные CTA ведут на `/ru/#consultation`.
- [ ] Согласовать `hourly_limit` и `phone_daily_limit`, не менять production ради
  теста. Привязку проверять без чтения заявок, контактов и истории клиник;
  записать только совпадает/не совпадает, не содержимое строки.

## 3. Защита и доставка — изолированная среда

- [ ] Настоящий Turnstile подключён к тестовому домену. Сервер подтверждает
  `success`, hostname и action `site_inquiry`. Имитация не заменяет Cloudflare.
- [ ] Отсутствующий, просроченный или повторный challenge не создаёт заявку.
- [ ] Внешнее ограничение настроено на `/api/crm/site-inquiry`, не на вход или
  записи CRM. Локальные 60 попыток/минуту на экземпляр не заменяют WAF.
  Лимиты согласовать и проверить в тестовой среде; production не нагружать.
- [ ] Проверить HTTPS, Origin, CSP, `/medina-site/form.js`, CSS, логотип и виджет.
  Запрет браузерного доступа не обходить.
- [ ] Согласие и заявка сохраняются вместе только в тестовом маркетинговом
  пространстве; успех UI означает сохранение. Отказ хранения не даёт успеха.
- [ ] Без согласия, с чужим Origin/tenant-параметром и невалидным телом нет записи.
- [ ] Потеря ответа и повтор с прежним requestKey не создают дубль; изменённые
  данные с прежним ключом дают конфликт. После успеха повтор закрыт.
- [ ] Политика отражает антибот-сервис и обработку контактов, хранение без
  автоматического срока; версия согласия согласована, ручное удаление в `leads`
  и `crm_site_inquiries` реализовано и проверено на фикстуре.
- [ ] Закрыт пробел аудита 27 сентября: удаление lead само по себе сохраняет
  персональные данные в receipts с NULL lead_id. Учтены все повторы и копии,
  не затронуты другие пространства. Информационная `/data-deletion` и зелёные
  characterization/handler-тесты не заменяют готовый процесс удаления.

Контакты не попадают в URL, localStorage, логи или аналитику; секрет не попадает
в HTML. Публичный site key не секрет. Не отправлять тестовую форму в production.
