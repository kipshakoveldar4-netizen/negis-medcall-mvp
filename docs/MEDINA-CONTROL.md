# Medina Control — портал владельца платформы

Отдельное приложение в `artifacts/medina-control`: клиники, подписки и выручка
платформы на своём домене, вне CRM, которой пользуются клиники. Статический
сайт без собственных serverless-функций: все данные приезжают из существующего
API продукта, авторизация — тот же Supabase и тот же список владельцев
платформы `MEDINA_PLATFORM_OWNER_IDS`.

## Как развернуть (делает владелец, ~10 минут)

1. **Создать второй проект Vercel** из того же репозитория
   `negis-medcall-mvp`: Add New → Project → выбрать репозиторий.
   - Root Directory: `artifacts/medina-control`
   - Framework: Vite (определится сам), команды сборки не менять.
2. **Переменные окружения нового проекта** (значения — те же, что у
   одноимённых переменных основного проекта):
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   - `VITE_MEDINA_API_URL` — необязательно; по умолчанию портал ходит на
     канонический адрес API. Задавать, только если адрес API сменится.
3. Deploy. Vercel выдаст адрес вида `https://<имя-проекта>.vercel.app`.
4. **В основном проекте** (`negis-medcall-mvp-api-server`) добавить переменную
   `MEDINA_CONTROL_ORIGINS=https://<имя-проекта>.vercel.app` и передеплоить
   (Redeploy последнего деплоя достаточно). Пока переменная пуста, API отвечает
   только своему домену — портал увидит отказ сети.
5. Открыть портал, войти своей почтой и паролем. Право на данные проверяет
   сервер по `MEDINA_PLATFORM_OWNER_IDS`; чужой аккаунт увидит «страницы нет».

Свой домен (например `control.medina.kz`) подключается позже поверх того же
проекта: Domains → Add в настройках проекта, плюс тот же origin через запятую
в `MEDINA_CONTROL_ORIGINS`.

## Что где лежит

- `artifacts/medina-control` — приложение (Vite/React, свой компактный стиль).
- `lib/auth/cors.ts` — кросс-доменный доступ к `/api/crm/*`: только для
  источников из `MEDINA_CONTROL_ORIGINS`, пустой список = как раньше.
  Авторизацию CORS не ослабляет: каждый запрос несёт Bearer-токен.
- `scripts/src/medina-control-portal.test.ts` — пины MC1–MC8
  (`pnpm run test:control-portal`).

## Локальная разработка

`pnpm --filter @workspace/medina-control run dev` — порт 5174. Портал пойдёт на
production-API; чтобы браузер разрешил запросы с localhost, владелец добавляет
`http://localhost:5174` в `MEDINA_CONTROL_ORIGINS` (через запятую) — или
временно задаёт `VITE_MEDINA_API_URL` на локальный dev-сервер CRM.

## Что дальше (по презентации, ещё не написано)

Карточка клиники, сигналы здоровья и рекомендации клиникам. Пункты меню
появятся вместе с кодом: раздел-обещание в этом продукте не вешают. Страница
`/platform` внутри CRM удаляется отдельным коммитом ПОСЛЕ того, как владелец
подтвердит, что портал развёрнут и работает.
