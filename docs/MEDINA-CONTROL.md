# Medina Control — портал владельца платформы

Отдельное приложение в `artifacts/medina-control`: клиники, подписки и выручка
платформы на своём домене, вне CRM, которой пользуются клиники. Статический
сайт без собственных serverless-функций: все данные приезжают из существующего
API продукта, авторизация — тот же Supabase и тот же список владельцев
платформы `MEDINA_PLATFORM_OWNER_IDS`.

## Текущая тестовая подготовка

CRM Preview не публикует отдельную форму Medina Control. Новые проекты,
production-выпуск, домены и перенос рабочих настроек здесь не разрешены.
Подготовка локального портала не создаёт аккаунты и не выдаёт доступы.

Все три значения должны быть заданы явно:

- `VITE_MEDINA_API_URL`: полный origin выбранного API, без пути, query,
  fragment и логина/пароля. Умолчания на production больше нет.
- `VITE_SUPABASE_URL`: полный origin выбранной Auth/БД.
- `VITE_SUPABASE_ANON_KEY`: только публичный JWT с ролью anon или publishable
  ключ. Никаких административных ключей в клиентском приложении.

Проверка формата/роли ключа не проверяет его подпись и не подтверждает доступ:
публичный ключ и пароль окончательно проверяет выбранный Supabase Auth.

Для текущей изолированной проверки дополнительно требуется
`VITE_MEDINA_CONTROL_MODE=isolated-preview`. Этот режим принимает только
medina-os-site-test (`ukiobbwsdoblooynzlnx`) и immutable Preview существующего
проекта/команды. Production, main/branch aliases, другой проект/команда, база,
HTTP-адрес, query и необычный порт не допускаются. На 14 октября API-кандидат:
`https://negis-medcall-mvp-api-server-ciu49f7sd-yeldar-s-projects.vercel.app`.
Новый разрешённый выпуск выбирают явно; stable alias использовать нельзя.

При отсутствующей или неверной конфигурации форма входа заблокирована,
подписка/обновление Auth и API-запросы не запускаются. API-redirect запрещён:
переадресация не должна переносить административное действие на другой адрес.
Это клиентский предохранитель, не замена серверной проверки доступа.

Для настоящего тестового owner bootstrap отдельно согласовать:

- точный локальный origin портала и только branch-specific
  `MEDINA_CONTROL_ORIGINS` тестового API;
- временный серверный платформенный доступ существующего тестового владельца
  через `MEDINA_PLATFORM_OWNER_IDS`, без изменений рабочих ролей;
- создание отдельного тестового пространства/owner, логин и timezone;
- точный тестовый перевыпуск API, необходимый после разрешённых env-изменений.

Пустые CORS/allowlist не обходить прокси, прямым SQL, рабочим Control или
Supabase Admin. Рабочие и общие Preview env не редактировать. Пароль и финальную
отправку создания выполняет человек. После проверки временный доступ и CORS
восстановить в прежнее состояние в согласованном тестовом выпуске.

Восстановление project env не отзывает доступ уже созданного immutable
deployment: Vercel применяет новые значения только к будущим deployments
([документация](https://vercel.com/docs/environment-variables/managing-environment-variables)).
Поэтому временный Preview с платформенным доступом также нужно вывести из
эксплуатации; удаление конкретного выпуска согласовать непосредственно перед
действием. Не удалять проект, базу, Auth пользователей или исходный код. Пока
этот выпуск существует, полное закрытие временного доступа не объявлять готовым.

## Что где лежит

- `artifacts/medina-control` — приложение (Vite/React, свой компактный стиль).
- `lib/auth/cors.ts` — кросс-доменный доступ к `/api/crm/*`: только для
  источников из `MEDINA_CONTROL_ORIGINS`, пустой список = как раньше.
  Авторизацию CORS не ослабляет: каждый запрос несёт Bearer-токен.
- `scripts/src/medina-control-portal.test.ts` — проверки CORS/портала;
  `scripts/src/medina-control-isolation.test.ts` — конфигурация и сетевой отказ
  (`pnpm run test:control-portal`).

## Локальная разработка

`pnpm --filter @workspace/medina-control run dev` — порт 5174. Без трёх явно
заданных значений портал остаётся заблокирован и никуда не входит. В dev
удалённые API/Auth требуют изолированного режима: обычные production значения
из локального env не дают войти. HTTP origin для API/Auth допускается только
в dev и только на loopback; изолированный
облачный режим всё равно требует указанный выше HTTPS Preview и тестовую БД.
Для безопасного просмотра ошибки конфигурации запускать с пустыми API/Auth
переменными процесса и `--host 127.0.0.1`; это перекрывает случайный локальный
env. Не добавлять localhost к production CORS ради локальной проверки.

Не удалять рабочие маршруты и не заменять интерфейс действующей CRM ради
тестового онбординга. Обзор, карточка и операторы уже реализованы; текущая
очередь приёмки и ограничения находятся в `docs/DELIVERY-CYCLES.md`.

### Ручная настройка тестовой формы, 14 октября

Автоматический перенос ключа/перезапуск ранее не был разрешён средством
выполнения. Ключ вводит человек; агент не повторяет отвергнутую команду и не
получает ключ из Vercel, браузера или буфера обмена. После ручного ввода агент
может помочь с отдельным запуском уже настроенного локального портала.

1. Открыть локальный `artifacts/medina-control/.env.local`. Он исключён из Git;
   подготовлены только режим и адреса из разрешённого плана, ключ пустой.
   Не переносить сюда настройки рабочей CRM. `.env.example` содержит лишь
   шаблон и не подключает портал автоматически.
2. В Supabase выбрать **medina-os-site-test**, ref `ukiobbwsdoblooynzlnx`, затем
   Project Settings -> API Keys. Вручную вставить существующий **publishable**
   ключ в `VITE_SUPABASE_ANON_KEY`; если используется legacy ключ, допустим
   только **anon**, не `service_role`. Не создавать новый ключ, не раскрывать
   secret/service-role, не присылать ключ или пароль в чат. Содержимое ключа
   не выводят: локальная проверка может вернуть только тип public/secret,
   без самого значения. Ключ другой базы не подходит, даже если публичный.
3. Перезапустить локальный портал вручную в PowerShell. Исходный безопасный
   процесс запущен с пустыми переменными: они имеют приоритет над `.env.local`,
   поэтому одного обновления страницы недостаточно. Код ниже прекращает только
   подтверждённый Vite именно этого приложения на loopback 5185; неизвестный
   слушатель приводит к остановке инструкции, а не к его завершению. Запуск
   нового процесса не меняет постоянные переменные Windows.

```powershell
Set-Location -LiteralPath 'C:/Users/Lenovo/Documents/Codex/medina-os'
$listeners = @(Get-NetTCPConnection -LocalPort 5185 -State Listen -ErrorAction SilentlyContinue)
if ($listeners.Count -gt 1) { throw 'На 5185 несколько слушателей. Остановитесь и сообщите об этом.' }
if ($listeners.Count -eq 1) {
  $listener = $listeners[0]
  $process = Get-CimInstance Win32_Process -Filter ('ProcessId = ' + $listener.OwningProcess)
  if ($listener.LocalAddress -ne '127.0.0.1' -or $process.Name -ne 'node.exe' -or
      $process.CommandLine -notlike '*medina-os\artifacts\medina-control\*' -or
      $process.CommandLine -notlike '*vite\bin\vite.js*' -or
      $process.CommandLine -notlike '*"--port" "5185" "--host" "127.0.0.1"*') {
    throw 'Процесс на 5185 не совпадает с тестовым порталом. Не завершайте его.'
  }
  Stop-Process -Id $listener.OwningProcess -ErrorAction Stop
}
Remove-Item Env:VITE_MEDINA_CONTROL_MODE, Env:VITE_MEDINA_API_URL, Env:VITE_SUPABASE_URL, Env:VITE_SUPABASE_ANON_KEY -ErrorAction SilentlyContinue
node 'C:/Users/Lenovo/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/pnpm/bin/pnpm.cjs' --filter @workspace/medina-control exec vite --port 5185 --host 127.0.0.1
```

4. Оставить окно PowerShell открытым и открыть `http://127.0.0.1:5185`.
   При корректной конфигурации исчезает сообщение «Портал не настроен» и
   доступны поля входа. Пока серверные platform owner/CORS отключены, это
   **не** готовое создание владельца. Не менять guards, использовать прокси
   или подставлять рабочую базу ради преодоления отказа.
5. После ручной настройки сообщить только «форма настроена». При внешней защите
   Vercel одних local CORS/allowlist недостаточно: этот случай подтверждён в
   emtfzjdz3 и описан выше. Не перевыпускать acc7145 ради повторения той же
   локальной попытки, не переносить bypass-токены в браузер. Следующий кандидат
   — защищённый same-origin выпуск 9a9d25a после точного согласия, не новая
   попытка отключить защиту. Вход eldar1@mail.ru, новый пароль и финальную
   отправку тестового онбординга выполняет человек. После проверки восстановить
   overrides и согласовать удаление конкретного временного deployment; старый
   g90saa028 уже удалён, использовать его нельзя.
