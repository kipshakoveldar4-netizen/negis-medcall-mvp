## Additional Findings

### 1. API false does not close every video requeue path

**Source-level reproduction, not an executed request:** set synthetic `VIDEO_OPTIMIZATION_ENABLED="false"`; supply an otherwise authorized, workspace-matching existing `awaiting_upload` job to `handleVideoJobs` with PATCH. The [false check](../lib/crm/server.ts#L7280) is inside POST only. The [PATCH branch](../lib/crm/server.ts#L7397) instead reads/validates the existing job, then [updates it to queued](../lib/crm/server.ts#L7421) without checking `config.enabled`. Likewise, the [failed-job retry branch](../lib/crm/server.ts#L7484) [requeues a failed job](../lib/crm/server.ts#L7504) before the ordinary POST [false check](../lib/crm/server.ts#L7536).

These branches retain workspace/status checks; this is not a browser authorization bypass. The gap is an off-switch contract: false blocks new-job POSTs but permits completion/retry to feed the queue, even after outstanding queued work was drained. With a separately running native worker, further processing remains possible. The delta warned about consuming existing jobs, not these routes replenishing them while false. Main must decide whether these transitions should remain available; this review changes no behavior.

### 2. Invalid Insights selection becomes server selection

The worker's [parser](../artifacts/meta-insights-worker/src/index.ts#L43) silently discards invalid UUID tokens. Explicit `META_INSIGHTS_WORKSPACE_IDS="false"` or `"typo"` therefore produces `[]`, and [serialization](../artifacts/meta-insights-worker/src/index.ts#L108) omits the field. This is the same request shape as intentionally omitting the restriction, not a refusal.

The server independently has this fallback: [parse/filter then choose scope](../lib/crm/server.ts#L9971) uses the entire allowlist when no valid requested UUID survives. A correctly signed body containing `workspaceIds: ["false"]` therefore also delegates to the allowlist. Even a comma-separated string of valid UUIDs can do this on the server because [readJsonArray](../lib/crm/server.ts#L359) splits strings only on whitespace. The normal worker avoids that particular mismatch by sending an array.

**Synthetic reproducible cases:** with server allowlist `[A]`, omitted / `[]` / `["false"]` resolve to `[A]`; valid `[B]` outside the allowlist resolves to `[]`, not `[A]`; `[A,"typo"]` silently becomes `[A]`. Here A and B were invented UUIDs, not tenant data. The delta covers intentionally empty selection, not an explicit malformed restriction broadening this way.

**Important boundary:** this does not bypass HMAC, the server allowlist, or [the provisioned-workspace check before any claim](../lib/crm/server.ts#L9994). That check [allows only the single configured META_WORKSPACE_ID](../lib/meta/workspace.ts#L40). An allowlist containing a different workspace aborts the whole cycle before the RPC; a blank/invalid server allowlist produces a [successful zero-claim response](../lib/crm/server.ts#L9989). The risk is unexpected selection of the already-authorized/provisioned workspace, possibly the wrong environment for a preview, not unrestricted cross-tenant execution.

### 3. Separate video buckets can still damage another queue partition

The delta records the unscoped [oldest-job selection](../artifacts/video-worker/src/worker.ts#L51). The additional consequence is that the worker [sets downloading, claim identity and increments attempts](../artifacts/video-worker/src/worker.ts#L64) before inspecting the row's workspace/bucket compatibility. The compare-and-set predicates are job ID and queued status, not an approved workspace/bucket.

**Source-level reproduction:** synthetic workspace B has the oldest queued job, valid identity/attempt data, and raw bucket `other-raw`; the synthetic worker is configured for `synthetic-raw`. Assuming successful mock claim updates, [processJob](../artifacts/video-worker/src/worker.ts#L112) sets `claimValidated=true` and updates the claim before [rejecting the bucket mismatch](../artifacts/video-worker/src/worker.ts#L120). Its [catch path](../artifacts/video-worker/src/worker.ts#L241) can then mark B's job failed with `video_raw_identity_invalid`. No download/transcode is necessary for that mutation. An asset is not marked failed in this mismatch case because `assetAuthorized` is still false.

Later [workspace-qualified updateClaim](../artifacts/video-worker/src/worker.ts#L85), raw-path prefixes, asset checks and finalization protect the claimed row's identity; they do not restrict the worker to an intended workspace. Bucket validation is post-claim, so custom bucket names are not an isolation boundary. A valid foreign-workspace job using the configured buckets is also eligible for full processing. Zero foreign-job mutations, not just zero media uploads, is the prerequisite for any future shared-queue isolation claim.

## Queue Boundary Details

- **Video:** [createSupabase](../artifacts/video-worker/src/worker.ts#L36) uses the configured project and service-role key directly. Claim selection has no approved-workspace input. Unique worker IDs and workspace-qualified storage paths prevent neither selection nor first mutation of another workspace's row. Separate queue/project authority must precede any claim; this review does not propose or implement Main's architecture.
- **Insights HTTP:** the handler [passes effectiveWorkspaceIds explicitly to the claim RPC](../lib/crm/server.ts#L10029), then [checks returned workspace identity](../lib/crm/server.ts#L10047) before sync. Invalid returned rows are skipped only after the RPC has already claimed them; this is defense in depth, not proof of zero cross-workspace claim mutation. A validated background launch can reach [Meta Insights retrieval](../lib/crm/server.ts#L9694), so a signed cycle is not a local/read-only preview probe.
- **Insights SQL source, not database state:** [migration 022](../migrations/022_meta_insights_scheduler_foundation.sql#L160) defines `p_workspace_ids default null`; [NULL removes the workspace restriction](../migrations/022_meta_insights_scheduler_foundation.sql#L202), whereas an empty array matches no workspace. It [leases/mutates rows](../migrations/022_meta_insights_scheduler_foundation.sql#L206) and [grants execution to service_role only](../migrations/022_meta_insights_scheduler_foundation.sql#L251), revoking public/anon/authenticated. The normal HTTP path does not pass NULL or call it with empty effective scope. Do not reuse this RPC in a future harness with an omitted argument or infer deployed grants/migrations from this text.
